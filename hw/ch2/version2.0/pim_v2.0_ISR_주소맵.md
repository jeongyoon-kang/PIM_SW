# PIM 에뮬레이터 v2.0 — ISR 필드 · 사용법 · 주소 맵

작성 2026-09-10. 대상 = **ISR 프로그램을 만드는 소프트웨어**와 **호스트 bring-up 코드**.

v2.0 은 open-page + per-bank row buffer 로 바뀌면서 ISR 워드를 다시 묶었고(repack),
violation 통계를 dispatcher 의 AXI4-Lite 안으로 옮겼다. 그 두 가지 때문에 v1 시절
문서의 비트 위치와 주소가 **전부 어긋난다**. 이 문서가 v2.0 의 사용자용 정본이다.

숫자가 어긋나면 RTL 이 이긴다.

# 1. ISR 워드 (256 bit)

```
 [5:0]     COL          6   row 안의 시작 beat (0..63)
 [22:6]    ROW/GPR_ADDR 17  opcode 가 해석을 정한다 (아래 표)
 [26:23]   BK           4   채널 안의 뱅크 번호
 [34:27]   CH_MASK      8   목적지 채널 비트마스크
 [35]      T            1   accumulator latch 선택 -> 뱅크 cmd latch_sel
 [45:36]   OPSIZE      10   beat 개수
 [50:46]   OPCODE       5
 [66:51]   pu_mask     16   연산을 실행하는 뱅크 집합
 [146:67]  route[16]   80   5b x 16. 뱅크 n 의 출력 목적지
 [162:147] gb_mc_mask  16   GB(BUF) 가 소스일 때 수신 뱅크 집합
 [179:163] GPR_ADDR2   17   GPR<->DRAM 쌍(WR_SBK/RD_SBK) 전용 두 번째 주소
 [255:180] --          76   미사용, 반드시 0
```

**v1 과 다르다.** v1 은 `OPCODE [63:59]`, `pu_mask [93:78]`, `route [175:96]` 였고
중간에 죽은 구멍이 네 군데(93 비트) 있었다. v2.0 은 그 구멍을 없애고 위로 몰았다 —
`[255:180]` 76 비트는 상위 끝에 붙어 있고, **0 이 아니면 시뮬레이션에서 한 번
알린다**(`ISR_UNUSED_*`). 중간에 구멍이 없으므로 필드를 실수로 밟을 수 없다.

## route[n] 부호화

`route[n]` 은 **뱅크 n 이 내보낼 목적지**를 5비트로 적는다.

| 값 | 뜻 |
|---|---|
| `0..15` | 그 번호의 뱅크 |
| `16` | Global Buffer (BUF) |
| `31` | 없음 (NULL) — 이 뱅크는 소스가 아니다 |

`gb_mc_mask` 는 방향이 반대다 — **GB 가 뱅크들로 뿌리는** 집합이다.
0 이 아니면 multicast(마스크된 뱅크 전부가 ready 여야 1 beat, lockstep),
0 이면 unicast.

# 2. opcode 별 비트 해석

**한 opcode 가 ISR 워드 256 비트를 어떻게 읽는지**를 opcode 마다 전부 적는다.
필드 위치 자체는 §1 과 같고 바뀌지 않는다 — 바뀌는 것은 **같은 자리를 어떻게
해석하고, 무엇을 요구하고, 무엇을 무시하는가** 다.

표의 "값" 칸은 소프트웨어가 그 자리에 무엇을 넣어야 하는지다.

| 표기 | 뜻 |
|---|---|
| **필수** | 이 opcode 의 동작을 정한다. 틀리면 조용히 틀린 결과가 나온다 |
| **0** | 반드시 0 이어야 한다 |
| 무시 | 하드웨어가 읽지 않는다. 0 을 권한다 |
| don't care | 읽기는 하지만 디코더가 통째로 덮어쓴다 |

## 2.0 opcode 값과 ROW 필드의 해석

`OPCODE` 는 `[50:46]` 5 비트다. 그리고 **`[22:6]` 한 자리를 opcode 가 두 가지로
해석한다** — 여기를 헷갈리면 엉뚱한 메모리를 읽는다.

| opcode | 값 | `[22:6]` 의 해석 | 계열 (§2.9) |
|---|---|---|---|
| `MAC` | `0x0C` | DRAM row | BANK |
| `EWMUL` | `0x0D` | DRAM row | BANK |
| `COPY` | `0x0E` | DRAM row | BANK |
| `WRVEC` | `0x0F` | **GPR 워드 주소** | REGISTER |
| `RD_MAC` | `0x10` | **GPR 워드 주소** (결과가 착지할 곳) | REGISTER |
| `EOS` | `0x11` | 무시 | 무관 |
| `WR_SBK` | `0x12` | DRAM row (GPR 쪽은 `GPR_ADDR2`) | 무관 |
| `RD_SBK` | `0x13` | DRAM row (GPR 쪽은 `GPR_ADDR2`) | 무관 |

`0x00`~`0x0B`, `0x14`~`0x1F` 는 정의되지 않았다. **디코더가 막지 않는다** — 정의되지
않은 opcode 를 넣으면 EC 가 아무 뱅크 트래픽도 내지 않고 은퇴시키거나, 마스크 필드를
그대로 해석해 예측할 수 없이 동작한다.

## 2.1 MAC — `0x0C`

곱셈-누산. **`gb_mc_mask` 가 0 이냐 아니냐로 두 형태가 갈린다** — 이것이 소스 선택자다
(`pim_decode.v`: `gb_sourced = (gb_mc != 0)`).

### (a) GB 소싱 — `gb_mc_mask != 0`

벡터가 Global Buffer 에 있다. 먼저 `WRVEC` 으로 채워둬야 한다.

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **필수** | 행렬이 있는 row 안의 시작 beat. `COL + OPSIZE ≤ 64` |
| `[22:6]` | `ROW` | 17 | **필수** | 행렬이 있는 DRAM row |
| `[26:23]` | `BK` | 4 | 조건부 | **`pu_mask` 가 0 일 때만** 읽힌다 — 그때 `pu_mask = 1 << BK` 로 정규화된다. `pu_mask` 를 채웠으면 무시 |
| `[34:27]` | `CH_MASK` | 8 | **필수** | 목적지 채널 비트마스크. 0 이면 아무 데도 안 간다 |
| `[35]` | `T` | 1 | **필수** | 누산기 latch 선택 (0/1). 뱅크 micro-cmd 의 `latch_sel` 로 그대로 간다 |
| `[45:36]` | `OPSIZE` | 10 | **필수** | beat 수. 1 beat = BF16 16 개. `K` 길이 내적이면 `K/16` |
| `[50:46]` | `OPCODE` | 5 | `0x0C` | |
| `[66:51]` | `pu_mask` | 16 | **필수** | 연산을 실행할 뱅크 집합. **`gb_mc_mask` 와 같아야 한다** |
| `[146:67]` | `route[16]` | 80 | don't care | 디코더가 통째로 NULL 로 덮는다 (`route_ignore = gb_sourced && is_mac`). 0 으로 둬도 되고 31 로 채워도 된다 |
| `[162:147]` | `gb_mc_mask` | 16 | **필수** | GB 가 벡터를 뿌릴 뱅크 집합. **1-hot 16 종 / `0x1111`·`0x2222`·`0x4444`·`0x8888` / `0xFFFF`** 중 하나만 유효 |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | |
| `[255:180]` | — | 76 | **0** | 0 이 아니면 시뮬레이션이 한 번 알린다 (`ISR_UNUSED_*`) |

`gb_mc_mask` 가 위 값들 밖이면 invalid 다. **하드웨어가 자동으로 쪼개주지 않는다.**

### (b) peer 소싱 — `gb_mc_mask == 0`

벡터를 옆 뱅크에서 읽는다. **all-bank footprint 전용**이다 — MACSB/MAC4B 는 C/A
인코딩에 그 어휘가 없다.

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **필수** | 위와 같다 |
| `[22:6]` | `ROW` | 17 | **필수** | 위와 같다 |
| `[26:23]` | `BK` | 4 | 조건부 | `pu_mask` 가 0 일 때만 (위와 같다) |
| `[34:27]` | `CH_MASK` | 8 | **필수** | |
| `[35]` | `T` | 1 | **필수** | |
| `[45:36]` | `OPSIZE` | 10 | **필수** | |
| `[50:46]` | `OPCODE` | 5 | `0x0C` | |
| `[66:51]` | `pu_mask` | 16 | **필수** | 연산할 뱅크 집합 |
| `[146:67]` | `route[16]` | 80 | **필수** | 각 pu 뱅크에 **in-edge 정확히 1 개**, out-edge 없음. 나머지는 `31`(NULL) |
| `[162:147]` | `gb_mc_mask` | 16 | **0** | 0 이라는 것이 곧 peer 소싱이라는 뜻이다 |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | |
| `[255:180]` | — | 76 | **0** | |

## 2.2 EWMUL — `0x0D`

원소별 곱. **한 ISR 이 뱅크 셋을 서로 다른 역할로 동시에 굴린다** — feed(읽어서
공급) / exec(곱) / dst(결과 받아 쓰기).

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **필수** | 피연산자 row 안의 시작 beat |
| `[22:6]` | `ROW` | 17 | **필수** | 피연산자 DRAM row |
| `[26:23]` | `BK` | 4 | 조건부 | `pu_mask` 가 0 일 때만 — 그때 exec 뱅크가 `1 << BK` 가 된다 |
| `[34:27]` | `CH_MASK` | 8 | **필수** | |
| `[35]` | `T` | 1 | 무시 | EWMUL 은 누산기를 쓰지 않는다 |
| `[45:36]` | `OPSIZE` | 10 | **필수** | beat 수 |
| `[50:46]` | `OPCODE` | 5 | `0x0D` | |
| `[66:51]` | `pu_mask` | 16 | **필수, popcount == 1** | 곱을 수행하는 **exec 뱅크 하나**. 둘 이상이면 invalid |
| `[146:67]` | `route[16]` | 80 | **필수** | exec 로 들어오는 in-edge 1 개(= feed 뱅크가 exec 를 가리킨다) + exec 에서 나가는 out-edge 1 개(= exec 가 dst 를 가리킨다, dst 는 비-pu). 나머지 `31` |
| `[162:147]` | `gb_mc_mask` | 16 | **0** | |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | |
| `[255:180]` | — | 76 | **0** | |

디코더가 이것을 **뱅크별로 다른 micro-cmd** 로 펼친다 — feed 뱅크에 `READ`,
exec 뱅크에 `EWMUL`, dst 뱅크에 `WRITE` 가 **같은 사이클에** 나간다.
ILA 의 `o_dbg_ca` 에서 이 사이클은 `hetero` 비트가 1 로 보인다.

## 2.3 COPY — `0x0E`

뱅크 → 뱅크 복사. **Global Buffer 를 반드시 경유한다.**

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **필수** | 소스 row 안의 시작 beat |
| `[22:6]` | `ROW` | 17 | **필수** | 소스 DRAM row. **읽는 쪽과 쓰는 쪽이 이 한 자리를 공유한다** — 그래서 fused COPY 는 양쪽 오프셋이 같다 |
| `[26:23]` | `BK` | 4 | 무시 | COPY 는 `route` 가 소스를 정한다 (`pu_mask` 정규화 대상이 아니다) |
| `[34:27]` | `CH_MASK` | 8 | **필수** | |
| `[35]` | `T` | 1 | 무시 | |
| `[45:36]` | `OPSIZE` | 10 | **필수** | beat 수 |
| `[50:46]` | `OPCODE` | 5 | `0x0E` | |
| `[66:51]` | `pu_mask` | 16 | **0** | 연산이 없다 |
| `[146:67]` | `route[16]` | 80 | **필수** | 소스 뱅크 `n` 의 필드에 목적지를 적는다 — `16`(=GB) 이면 읽기 반쪽, 뱅크 번호면 **fused**(아래). 나머지 `31` |
| `[162:147]` | `gb_mc_mask` | 16 | 조건부 | 0 이 아니면 **쓰기 반쪽** — GB 가 이 뱅크 집합으로 뿌린다. 0 이면 읽기 반쪽 |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | |
| `[255:180]` | — | 76 | **0** | |

**fused COPY.** `route[n]` 이 뱅크를 가리키면(= 뱅크→뱅크) EC 가 이 한 발을 **두
위상으로 쪼갠다**: 먼저 소스 row 를 GB 로 옮기고(읽기 반쪽), 끝나면 GB 에서 목적지
뱅크로 쓴다(쓰기 반쪽). 소프트웨어는 한 발만 쓰면 되고, `global_bus` 와 디코더는
fused 라는 사실을 모른다 — EC 가 ISR 워드를 다시 써서 평범한 COPY 반쪽으로 보여준다.

## 2.4 WRVEC — `0x0F`

GPR 의 벡터를 Global Buffer 에 채운다. `MAC`(GB 소싱)의 선행 명령이다.

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **0** | GPR 에는 열이 없다 |
| `[22:6]` | `GPR_ADDR` | 17 | **필수** | **GPR 워드 주소** (DRAM row 아님). 여기서부터 `OPSIZE` 개를 연속으로 읽는다 |
| `[26:23]` | `BK` | 4 | **0** | 뱅크를 건드리지 않는다 |
| `[34:27]` | `CH_MASK` | 8 | **필수** | |
| `[35]` | `T` | 1 | 무시 | |
| `[45:36]` | `OPSIZE` | 10 | **필수** | beat 수. **64 를 넘기지 마라** — GB 가 64 entry 인데 막아주는 것이 없어서 조용히 감아 덮어쓴다 (V4) |
| `[50:46]` | `OPCODE` | 5 | `0x0F` | |
| `[66:51]` | `pu_mask` | 16 | **0** | |
| `[146:67]` | `route[16]` | 80 | **전부 31** | |
| `[162:147]` | `gb_mc_mask` | 16 | **0** | |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | GPR 주소는 `[22:6]` 을 쓴다. 이쪽이 아니다 |
| `[255:180]` | — | 76 | **0** | |

EC 가 `gb_wr_start` 로 write 포인터를 0 으로 되돌린 뒤 `OPSIZE` beat 를 채운다.
**이전 벡터는 덮어써진다.** 이후 `MAC` 은 읽기 포인터가 write 포인터에서 저절로
순환하므로 같은 벡터를 몇 번이든 다시 읽는다 — 되감기 신호가 따로 없다.

## 2.5 RD_MAC — `0x10`

누산 결과를 읽어 GPR 에 쓴다. **전 뱅크 브로드캐스트가 opcode 고유 의미**다
(AiM RDMAC 과 동일 — 뱅크·행·열 필드가 없다).

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **0** | |
| `[22:6]` | `GPR_ADDR` | 17 | **필수** | 결과가 착지할 **GPR 워드 주소** |
| `[26:23]` | `BK` | 4 | **0** | 전 뱅크에서 모은다 |
| `[34:27]` | `CH_MASK` | 8 | **필수, 1-hot** | 여러 채널이 같은 GPR 주소에 쓰면 충돌한다 |
| `[35]` | `T` | 1 | **필수** | 어느 latch 를 읽고 비울지 |
| `[45:36]` | `OPSIZE` | 10 | **0 고정** | 결과는 항상 집계 1 beat (16 lane × 16b) |
| `[50:46]` | `OPCODE` | 5 | `0x10` | |
| `[66:51]` | `pu_mask` | 16 | **0** | |
| `[146:67]` | `route[16]` | 80 | **전부 31** | |
| `[162:147]` | `gb_mc_mask` | 16 | **0** | |
| `[179:163]` | `GPR_ADDR2` | 17 | **0** | |
| `[255:180]` | — | 76 | **0** | |

읽으면 latch 가 비워진다(read-clear). 착지한 1 beat 안에서 **lane `b` = 뱅크 `b`**,
즉 `[b*16 +: 16]` 이 뱅크 `b` 의 BF16 결과다.

## 2.6 EOS — `0x11`

커널 종료. **열려 있는 모든 뱅크를 PRE 한다.**

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[45:36]` `[35]` `[26:23]` `[22:6]` `[5:0]` | `OPSIZE` `T` `BK` `ROW` `COL` | — | **0** | 전부 무시된다. 0 으로 둬라 |
| `[34:27]` | `CH_MASK` | 8 | **필수** | 닫을 채널. 여러 채널을 동시에 끝내려면 여러 비트 |
| `[50:46]` | `OPCODE` | 5 | `0x11` | **이 필드만 의미가 있다** |
| `[66:51]` `[146:67]` `[162:147]` `[179:163]` `[255:180]` | 마스크 전부 | — | **0** | |

**반드시 프로그램의 마지막에 넣어야 한다.** open-page 라서 계산 결과가 row buffer 에
남아 있고, `EOS` 의 PRE 가 그것을 DRAM 에 되쓴다. 하드웨어는 스스로 flush 하지
않는다. EOS 없이 끝내면 호스트가 읽는 메모리는 아직 갱신되지 않은 상태다.

EOS 는 **물리적으로 끝날 때까지** 기다렸다 은퇴한다(`i_bank_busy` 가 다 내려갈 때까지).
`STATUS[31]`(done)이 그 뒤에 선다. 이 PRE 는 **all-bank 로 과금**된다 — 예산이
`T_RP` 가 아니라 `T_RP_AB` 다 (§3.2.4).

## 2.7 WR_SBK — `0x12` / RD_SBK — `0x13`

GPR ↔ DRAM 을 한 발로 옮긴다. **채널 하나, 뱅크 하나.** 이 둘만이 DRAM 자리와 GPR
자리를 동시에 지목하므로, **`GPR_ADDR2` 를 읽는 유일한 opcode** 다.

| 비트 | 필드 | 폭 | 값 | 설명 |
|---|---|---|---|---|
| `[5:0]` | `COL` | 6 | **필수** | DRAM 쪽 row 안의 시작 beat |
| `[22:6]` | `ROW` | 17 | **필수** | DRAM 쪽 row |
| `[26:23]` | `BK` | 4 | **필수** | DRAM 쪽 뱅크 번호. **단일 뱅크다** |
| `[34:27]` | `CH_MASK` | 8 | **필수, 1-hot** | 단일 채널 |
| `[35]` | `T` | 1 | 무시 | |
| `[45:36]` | `OPSIZE` | 10 | **필수** | beat 수 |
| `[50:46]` | `OPCODE` | 5 | `0x12` / `0x13` | 방향을 정하는 것이 이 필드다 |
| `[66:51]` | `pu_mask` | 16 | 무시 | EC 가 덮어쓴다 |
| `[146:67]` | `route[16]` | 80 | 무시 | EC 가 덮어쓴다 |
| `[162:147]` | `gb_mc_mask` | 16 | 무시 | EC 가 덮어쓴다 |
| `[179:163]` | `GPR_ADDR2` | 17 | **필수** | **GPR 쪽 워드 주소** |
| `[255:180]` | — | 76 | **0** | |

방향은 opcode 가 정한다:

- `WR_SBK` (`0x12`) : GPR → GB → 뱅크
- `RD_SBK` (`0x13`) : 뱅크 → GB → GPR

**왜 route 로 표현하지 않는가.** `route` 값 공간에는 "GPR" 이라는 값이 없고
(`0..15` = 뱅크, `16` = GB, `31` = NULL), 게다가 `route` 는 **뱅크 소스별** 맵이라
GPR 소스를 적을 자리 자체가 없다. 그래서 opcode 가 방향을 정하고 필드를 직접 읽는다.

**왜 단일 뱅크인가.** 다중 뱅크 `RD_SBK` 는 여러 뱅크를 GB 하나와 GPR 스트림 하나에
끼워넣게 되어 착지 순서가 정의되지 않는다. 다중 뱅크 `WR_SBK` 는 브로드캐스트인데
그건 `COPY` 쓰기 반쪽(`gb_mc_mask` 다중 비트)이 이미 표현한다. 제한이 아니라 의미다.

EC 가 `route`/`gb_mc_mask` 를 내부에서 다시 써서 `COPY` 의 한쪽 반쪽으로 바꿔
디코더에 넘긴다. 그래서 디코더도 global bus 도 SBK 라는 opcode 를 모른다.

## 2.8 한눈에 보는 표

| opcode | `BK` | `T` | `pu_mask` | `route` | `gb_mc_mask` | `GPR_ADDR2` | `OPSIZE` |
|---|---|---|---|---|---|---|---|
| `MAC` (GB) | pu=0 일 때만 | 필수 | `= gb_mc_mask` | don't care | 1-hot / `0x1111`계열 / `0xFFFF` | 0 | beat 수 |
| `MAC` (peer) | pu=0 일 때만 | 필수 | exec 집합 | 각 pu 에 in-edge 1 | **0** | 0 | beat 수 |
| `EWMUL` | pu=0 일 때만 | 무시 | **popcount==1** | in 1 + out 1 | **0** | 0 | beat 수 |
| `COPY` | 무시 | 무시 | **0** | 소스 → 목적지 | 쓰기 반쪽의 목적지 | 0 | beat 수 |
| `WRVEC` | 0 | 무시 | **0** | 전부 31 | **0** | 0 | beat 수 |
| `RD_MAC` | 0 | 필수 | **0** | 전부 31 | **0** | 0 | **0 고정** |
| `EOS` | 0 | 무시 | **0** | 전부 31 | **0** | 0 | 무시 |
| `WR_SBK` | **필수** | 무시 | EC 가 덮어씀 | EC 가 덮어씀 | EC 가 덮어씀 | **필수** | beat 수 |
| `RD_SBK` | **필수** | 무시 | EC 가 덮어씀 | EC 가 덮어씀 | EC 가 덮어씀 | **필수** | beat 수 |

`CH_MASK` 는 모든 opcode 에서 필수이고, `RD_MAC`·`WR_SBK`·`RD_SBK` 는 **1-hot** 이라야
한다. `[255:180]` 76 비트는 모든 opcode 에서 **0** 이다.

## 2.9 REGISTER / BANK 모드 — opcode 가 모드를 요구한다

EC 는 채널마다 모드 하나를 가진다. ISR 을 받으면 **실행하기 전에** 지금 모드로 그 ISR 을
돌릴 수 있는지 보고, 안 되면 모드를 뒤집은 뒤 **nMOD 사이클 동안 아무것도 발행하지 않고
기다렸다가** 실행한다. 같은 모드면 기다림 없이 바로 실행한다.

| 계열 | opcode | 필요한 모드 |
|---|---|---|
| REGISTER | `WRVEC`, `RD_MAC` | REGISTER |
| BANK | `MAC`, `COPY`, `EWMUL` | BANK |
| 모드 무관 | `WR_SBK`, `RD_SBK`, `EOS`, 호스트 일반 메모리 요청 | 모드를 안 보고 안 바꾼다 |

- 리셋 직후는 **BANK**. doorbell(새 커널)에서 **초기화하지 않는다** — 이전 커널이 남긴 모드에서 시작한다.
- nMOD 는 CFR `T_MOD`(`0x034`)로 설정하고, 다른 타이밍 값과 같은 폭(10 비트)이다. 0 이면 전환은 일어나지만 기다림은 없다.
- 이 기다림은 violation 대상이 아니다.
- 비용을 줄이려면 **같은 계열 명령을 묶어서** 배치하라. `WRVEC → MAC → RD_MAC` 는
  전환이 두 번(각 nMOD) 든다.


## 유효성은 소프트웨어가 지킨다

`validity_gate` 는 타이밍 때문에 2026-07-29 fetch 경로에서 빠졌고, 2026-09-09 저장소에서
삭제됐다. **하드웨어는 아무것도 검사하지 않는다.** 규칙을 어긴 ISR 은 조용히 틀린 결과를

규칙 정본은 `docs/pim_isr_routing_spec_v2.5.md` §5 이고, 요지는 넷이다:

| | |
|---|---|
| V1 수신 유일 | 뱅크 하나는 최대 한 스트림의 목적지. route 값 중복 금지, route 값 ∩ gb_mc = ∅ |
| V2 역할 배타 | 비-pu 뱅크는 in/out 중 하나만. pu 뱅크는 in ≤1, out ≤1. self-route 금지 |

## 3.2 CFR (`0x0202_0040_0000`, 4 KiB)

### 3.2.1 레지스터 일람

4 KiB AXI4-Lite 창 하나가 **프로그램된 예산**과 **그 예산에서 나온 초과**를 함께 담는다.
채널별 `viol_csr` 인스턴스는 v2.0 에서 없어졌다 — 채널 수만큼 슬레이브를 늘리는 대신
한 슬레이브 안에서 채널을 주소로 가른다(`0x400 + ch*0x100`).

주소는 세 페이지로 나뉜다. **쓰기는 페이지 0 과 `0x800` 에만 먹는다** — 통계 페이지는
전부 RO 라, 호스트가 깨끗한 실행을 위조할 수 없다.

| 오프셋 | 이름 | 설명 |
|---|---|---|
| `0x000` | `CTRL` | doorbell · 채널 fan-out 모드 |
| `0x004` | `STATUS` | fetcher 상태와 done |
| `0x008` | `T_FAW` | tFAW — 4 ACT 창 |
| `0x00C` | `T_RRD` | tRRD — ACT→ACT 간격 |
| `0x010` | `T_RCD` | tRCD — ACT→CAS |
| `0x014` | `T_CCD` | tCCD — CAS→CAS |
| `0x018` | `T_RTP` | tRTP — 마지막 READ→PRE |
| `0x01C` | `T_RP` | tRP — **단일 뱅크** PRE→ACT |
| `0x020` | `T_WR` | tWR — 마지막 WRITE→PRE |
| `0x024` | `T_RAS` | tRAS — ACT→PRE |
| `0x028` | `PROG_LEN` | ISR 개수 (fetch 종료 조건) |
| `0x02C` | `RUN_CYC_LO` | 실행 사이클 수, 하위 32 비트 |
| `0x030` | `RUN_CYC_HI` | 같은 값의 상위 32 비트 |
| `0x034` | `T_MOD` | nMOD — REGISTER↔BANK 모드 전환 비용 |
| `0x038` | `T_RP_AB` | tRPab — **all-bank** PRE(PRECHARGE ALL)→ACT |
| `0x03C – 0x3FF` | (예약) | 읽으면 0, 써도 무시 |
| `0x400 – 0x7FF` | (통계) | 채널 `c`·뱅크 `b` 당 0x10 블록 — 아래 3.2.10 |
| `0x800` | `VIOL_CTRL` | 통계 전체 클리어 |
| `0x804` | `VIOL_ANY0` | ch0·ch1 뱅크 비트맵 |
| `0x808` | `VIOL_ANY1` | ch2·ch3 뱅크 비트맵 |

타이밍 레지스터 9 개(`0x008`~`0x024`, `0x034`, `0x038`)는 폭·단위·기본값이 모두 같아
3.2.3 에 한 번만 적는다.

### 3.2.2 CTRL (`0x000`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[0]` | `doorbell` | 0 | W1 | 1 을 쓰면 1 사이클 펄스가 나가 fetcher 가 프로그램을 시작한다. 저장되지 않고 자동으로 내려가므로, 0 을 되쓰는 것을 잊어도 fetcher 가 물리지 않는다. 언제나 0 으로 읽힌다. |
| `[1]` | `mode` | 0 | RW | 채널 fan-out. 0 = NORMAL(`CH_MASK` 를 따른다), 1 = ALL_BANK. 이 비트만 쓰는 것은 doorbell 을 울리지 않는다. |
| `[31:2]` | 예약 | 0 | RO | 써도 아무 일도 없고 언제나 0 으로 읽힌다. |

### 3.2.3 타이밍 레지스터 (`0x008`~`0x024`, `0x034`, `0x038`)

아홉 개가 같은 모양이다.

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[9:0]` | `value` | 0 | RW | 사이클 수. `TW = 10` 이므로 0~1023. |
| `[31:10]` | 예약 | 0 | RO | 써도 버려지고 언제나 0 으로 읽힌다. |

- **단위는 PL 클럭 사이클이다.** `N` 을 쓰면 해당 사건 뒤 `N` 사이클이 지나야 다음 발행이 허용된다. EC 가 `N-1` 을 로드하고 0 에서 조건 충족으로 보므로 **0 과 1 은 같은 뜻**(대기 없음)이다.
- **리셋 직후 전부 0 이다.** 즉 타이밍 없이 최대 속도로 발행한다. 커널을 돌리기 전에 반드시 채워야 한다.
- **doorbell 에 묶여 있지 않다.** EC 가 매 사이클 값을 받으므로 쓰는 즉시 반영된다. 실행 중에는 바꾸지 마라 — 예산이 바뀌는 순간 violation 판정 기준도 같이 바뀐다.
- 모든 예산은 **EC 가 소유한다.** 뱅크에는 타이밍 입력 포트가 없다.

### 3.2.4 T_RP 와 T_RP_AB 를 나눠 쓰는 법

한 뱅크를 닫는 PRECHARGE 와 전체를 닫는 PRECHARGE ALL 은 **서로 다른 DRAM 명령**이고
회복 시간도 다르다. EC 는 처음부터 두 포트(`i_nrp_pb` / `i_nrp_ab`)로 받고 있었지만
CFR 에 레지스터가 하나뿐이라 둘 다 `T_RP` 에 물려 있었고, PRECHARGE ALL 을 단일 뱅크
시간으로 **과소 계상**하고 있었다. `0x038` 이 그 자리를 채운다.

어느 쪽으로 과금되는지는 발행된 PRE 가 몇 개 뱅크를 물었는지가 아니라 **명령의 종류**가
정한다 (RTL 의 `w_pre_is_ab`):

| 상황 | 적용 예산 |
|---|---|
| ISR 이 all-bank 마디 (활성 뱅크 = 16 전부) | `T_RP_AB` |
| `EOS` 의 flush (열린 뱅크를 전부 닫는다) | `T_RP_AB` |
| 그 외 — 마스크에 뱅크가 몇 개 걸렸든 | `T_RP` |
| 호스트 일반 메모리 경로 (언제나 단일 뱅크) | `T_RP` |

같은 기준이 3.2.10 의 `PRE_DRAIN` violation 예산에도 그대로 쓰인다.

### 3.2.5 STATUS (`0x004`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[3:0]` | `fsm_state` | 0 | RO | fetcher 상태. `0` IDLE / `1` ISSUE / `2` PRESENT / `3` DONE. |
| `[21:4]` | 예약 | 0 | RO | 언제나 0. v1 에서 validity_gate 보고가 쓰던 자리이고, gate 가 삭제되면서 빈 비트가 됐다. |
| `[30:22]` | 예약 | 0 | RO | 언제나 0. |
| `[31]` | `done` | 0 | RO | 프로그램의 마지막 ISR 이 EC 에 수락됐다. 마지막이 `EOS` 면 EC 가 그것을 *시작*한 시점이지, 되쓰기가 끝난 시점이 아니다. |

### 3.2.6 PROG_LEN (`0x028`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[13:0]` | `prog_len` | 0 | RW | 이번 프로그램의 ISR 개수. fetcher 가 이 개수만큼 꺼내고 멈춘다. IMEM 이 16K 워드라 폭이 14 비트다. |
| `[31:14]` | 예약 | 0 | RO | 써도 버려지고 언제나 0 으로 읽힌다. |

doorbell 전에 써야 한다. fetcher 는 시작할 때 값을 한 번 래치한다.

### 3.2.7 RUN_CYC_LO (`0x02C`) / RUN_CYC_HI (`0x030`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[31:0]` | `run_cyc_lo` | 0 | RO | 64 비트 카운터의 하위 절반. |
| `[31:0]` | `run_cyc_hi` | 0 | RO | 상위 절반. |

doorbell 에서 0 으로 지워지고, fetcher 가 도는 동안 매 사이클 늘다가, `STATUS[31]` 이
서는 사이클에 멈춰 **다음 doorbell 까지 그 값을 유지한다.**

- **EOS 의 뒷일은 포함되지 않는다.** 열린 뱅크를 PRE 해서 DRAM 에 되쓰는 시간은 이 값 뒤에 온다.
- **실행이 끝난 뒤에 읽어라.** LO 와 HI 를 따로 읽으므로, 세는 도중에 읽으면 두 읽기 사이에 LO 가 넘어가 값이 어긋난다.
- 64 비트인 이유는 32 비트면 100 MHz 에서 약 43 초에 넘치기 때문이다.

### 3.2.8 VIOL_CTRL (`0x800`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[0]` | `clrstats` | 0 | W1 | 1 을 쓰면 **모든 채널·모든 뱅크**의 플래그·카운트·최대값을 지운다. 저장되지 않고 자동으로 내려가므로, 호스트가 0 을 되쓰는 것을 잊어도 카운터를 0 에 묶어둘 수 없다. 언제나 0 으로 읽힌다. |
| `[31:1]` | 예약 | 0 | RO | 써도 아무 일도 없고 언제나 0 으로 읽힌다. |

### 3.2.9 VIOL_ANY0 (`0x804`) / VIOL_ANY1 (`0x808`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[15:0]` | `any_ch0` / `any_ch2` | 0 | RO | 뱅크 하나당 1 비트. 그 뱅크의 `STICKY[31]` 이 서 있는 동안 1. |
| `[31:16]` | `any_ch1` / `any_ch3` | 0 | RO | 같은 방식, 다음 채널. |

**이것을 먼저 읽어라.** 64 개 블록을 훑는 대신 두 번의 읽기로 범인 뱅크를 지목한다.

### 3.2.10 violation 통계 (`0x400` ~ `0x7FF`, 전부 RO)

채널 하나가 `0x100` 블록, 그 안에서 뱅크 하나가 `0x10` 블록을 갖는다.

```
주소 = 0x400 + ch*0x100 + bk*0x10 + reg
       ch = addr[9:8]   bk = addr[7:4]   reg = addr[3:2]
```

채널 0 뱅크 0 이 `0x400`, 채널 3 뱅크 15 가 `0x7F0` 이다. 뱅크·종류마다 **세 숫자**를
남긴다 — sticky 플래그, 포화 카운트, 최악 초과. **사건별 로그는 없다.** 타이밍 위반은
사후에 고칠 수 있는 것이 아니고, 유일한 대응이 예산을 키워 다시 돌리는 것이라 로그가
할 일이 없기 때문이다.

| 뱅크 기준 오프셋 | 이름 | 설명 |
|---|---|---|
| `+0x00` | `STICKY` | 종류별 sticky 플래그 |
| `+0x04` | `CNT` | 종류별 발생 횟수 |
| `+0x08` | `MAX` | 종류별 최악 초과 사이클 |
| `+0x0C` | (예약) | 읽으면 0 |

**종류는 둘뿐이다.** v1 의 여섯 종류(tRCD/tCCD 를 읽기·쓰기로 나누고 recovery 와 EWMUL
drop 을 더한 것)는 v2.0 에서 사라졌다. 뱅크가 카운터를 하나도 갖지 않게 되면서, 뱅크가
자기 힘으로 위반을 선언할 수 있는 사건이 ACT 와 PRE 둘만 남았기 때문이다.

#### STICKY (뱅크 기준 `+0x00`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[0]` | `act_fill` | 0 | RO | 마지막 클리어 이후 이 뱅크에서 ACT_FILL 위반이 최소 한 번 났다. |
| `[1]` | `pre_drain` | 0 | RO | 같은 기간에 PRE_DRAIN 위반이 났다. |
| `[30:2]` | 예약 | 0 | RO | 언제나 0. |
| `[31]` | `any` | 0 | RO | 위 두 플래그의 OR. `VIOL_ANY*[b]` 가 그대로 이 비트를 비추므로, 뱅크별 읽기로 비트맵을 확인할 수 있다. |

#### CNT (뱅크 기준 `+0x04`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[7:0]` | `cnt_act_fill` | 0 | RO | ACT_FILL 발생 횟수. `0xFF` 에서 **포화하고 랩하지 않는다** — 가득 찬 값은 "최소 255 번"이라는 뜻이다. |
| `[15:8]` | `cnt_pre_drain` | 0 | RO | PRE_DRAIN 에 대해 같다. |
| `[31:16]` | 예약 | 0 | RO | 언제나 0. |

랩하지 않는 이유는 랩해서 0 이 되면 **위반이 없었던 실행과 구분되지 않기** 때문이다.

#### MAX (뱅크 기준 `+0x08`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[9:0]` | `max_act_fill` | 0 | RO | ACT_FILL 의 최악 초과, 사이클 단위. 설정된 예산 대비 넘긴 양이다. 폭은 `VIOL_OVW = 10`. |
| `[15:10]` | 예약 | 0 | RO | 언제나 0. |
| `[25:16]` | `max_pre_drain` | 0 | RO | PRE_DRAIN 에 대해 같다. |
| `[31:26]` | 예약 | 0 | RO | 언제나 0. |

#### 두 종류의 뜻과 측정 식

EC 가 ACT 또는 PRE 를 발행하고, 그 뱅크의 `accept_ok` 가 다시 설 때까지 기다린 사이클을
재서 예산과 비교한다. `accept_ok` 는 뱅크가 EC 에 올려보내는 **유일한** 타이밍 신호다.

```
elapsed = accept_ok 시점 − issue 시점
overrun = elapsed > budget ? elapsed − budget : 0

ACT_FILL   ACT 발행 → row buffer 채우기 완료   budget = T_RCD
PRE_DRAIN  PRE 발행 → 되쓰기 완료              budget = T_RP     (단일 뱅크)
                                                        T_RP_AB  (3.2.4 의 기준)
```

**나머지 예산에는 violation 이라는 개념이 없다.** `T_CCD`·`T_RAS`·`T_RTP`·`T_WR`·
`T_RRD`·`T_FAW` 는 EC 가 자기 발행 시점만으로 지키는 self-stall 이라 어길 수가 없다.
어겨질 수 있는 것은 물리 동작이 예산 안에 끝나지 않는 경우뿐이고, 그것이 위 두 종류다.

**읽어도 지워지지 않는다.** 지우려면 `VIOL_CTRL[0]` 에 1 을 쓴다.

## 3.3 채널 스위치 (`0x0202_0040_5000`, 4 KiB)

| 오프셋 | 이름 | 설명 |
|---|---|---|
| `0x000` | `MODE` | 호스트 주소 해석 방식 |
| `0x004` | `STATUS` | busy |

### 3.3.1 MODE (`0x000`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[0]` | `mode` | 0 | RW | 0 = ChRoBaCo(bypass), 1 = RoChBaCo(interleave). |
| `[31:1]` | 예약 | 0 | RO | 언제나 0. |

### 3.3.2 STATUS (`0x004`)

| 비트 | 필드 | 기본값 | 접근 | 설명 |
|---|---|---|---|---|
| `[0]` | `busy` | 0 | RO | 어느 포트든 트랜잭션이 떠 있다. |
| `[31:1]` | 예약 | 0 | RO | 언제나 0. |

**`MODE` 를 바꾸기 전에 `STATUS.busy == 0` 을 확인해야 한다.** 하드웨어가 막아주지 않는다.

## 3.4 데이터 평면 — BAR2 밖

| 주소 | 크기 | 대상 |
|---|---|---|
| `0x0204_0000_0000 + ch * 4 GiB` | 4 GiB | emulator_controller `s_axi` (채널 스위치 경유) |
| `0x40_0000_0000` | — | HBM. 뱅크 창 256 MiB, HBM 채널 `k` 의 PC0 = `+k*2 GiB`, PC1 = `+1 GiB` |

MC 의 `s_axi` 는 AXI 맵에는 있지만 **BAR2 밖**이다 — QDMA DMA 는 닿고 호스트 MMIO 는 닿지 않는다.

# 4. 커널 한 번 돌리는 순서

```
1. IMEM 에 ISR 프로그램을 쓴다            0x0202_0060_0000
   마지막 ISR 은 EOS 여야 한다
2. CFR 타이밍 레지스터 9 개를 채운다       0x008 ~ 0x024, 0x034, 0x038
3. PROG_LEN 에 ISR 개수를 쓴다             0x028
4. (선택) VIOL_CTRL[0]=1 로 통계를 지운다  0x800
5. CTRL[0]=1  -- doorbell                  0x000
6. STATUS[31] (done) 이 설 때까지 폴링     0x004
   (선택) RUN_CYC_LO/HI 로 실행 사이클 수    0x02C / 0x030
7. VIOL_ANY0/ANY1 을 읽는다                0x804 / 0x808
      0 이 아니면 그 실행의 타이밍 측정은 무효다 -- 예산을 못 지켰다는 뜻이므로
      K 를 키워 다시 돌려야 한다
8. 결과를 GPR 에서 읽는다                  0x0202_0000_0000 + GPR_ADDR*32
```

**7번을 건너뛰지 마라.** violation 이 났는데 결과만 읽으면, 그 숫자는 DRAM 타이밍을
재현한 값이 아니라 하드웨어가 못 따라간 값이다. 그 둘은 결과만 봐서는 구분되지 않는다.
